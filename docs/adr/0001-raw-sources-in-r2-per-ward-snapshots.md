# 一次情報の元ファイルはGitに入れず、R2に区ごとのスナップショットとして保管する

市から取得したPDF・HTML・Excel・CSVは24区分で約1GBあり、毎月更新される。Gitに入れるとリポジトリが際限なく膨らむため、`.gitignore` で除外し、非公開のR2バケットに `snapshots/<区id>/<取得日>/` と `snapshots/city/<取得日>/` の形で保管する。目視転記したJSON・抽出結果・生成した `facilities.json` はGitにコミットし、PRで差分をレビューする。`facilities.json` には、区ごとと全市共通のそれぞれどの取得日のスナップショットから作ったかを記録する。

保管を区ごとにしたのは、取得を1区ずつ確認しながら進める運用で、区によって空き情報の時点が違うまま公開することを許しているため。全市で1つのスナップショットにすると、一部の区だけを更新することができなくなる。

## Considered Options

- **Git LFSで全部コミットする**：毎月数百MBずつ増え、LFSの容量課金に触れやすい。
- **最新版だけを上書き保管する**：過去に公開したデータを再現できなくなる。
- **`data:fetch` のたびに自動でアップロードする**：確認前の壊れた取得結果まで保管されてしまう。アップロードは差分を確認したあとに `data:archive` で行う。
